# Open-source contribution mode

## 1. Purpose and applicability
Rules for optimizing external projects.

## 2. Detection signals
Applies when the repository is not the user's own.

## 3. What to inspect
Read CONTRIBUTING, code of conduct, style and test instructions; check license and contribution terms; review issues and discussions.

## 4. Metrics
Maintainer-accepted benchmarks and tests.

## 5. Common bottlenecks and anti-patterns
Needless rewrites, new dependencies, unfocused patches, disclosing nothing about AI assistance when required.

## 6. Candidate optimization techniques
Focused patches with tests and benchmark evidence; explain problem, fix, tradeoffs and impact; follow conventions.

## 7. Runtime tunables versus build-time changes
Not applicable.

## 8. Hardware-dependent decisions (RACE) versus universal changes (/optimize)
Universal changes only.

## 9. Compatibility and version considerations
Match supported versions.

## 10. Security, privacy, accessibility, data integrity
No push, release, comment or PR without explicit user authorization.

## 11. Validation and benchmark methodology
Run the project's own checks.

## 12. Rollback considerations
Keep branches isolated and revertible.

Project spec section 9 and general engineering practice; no external documents fetched for this file (specifics **unverified**). Last reviewed: 2026-11-07.
